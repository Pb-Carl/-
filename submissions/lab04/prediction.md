# 实验 04：事务结果预测

学号 2410311319。主实验每批处理 500 条已清洗事件；首次处理 20,000 条后预计数据库 20,000 行、检查点 20,000。重放前 100 条因事件 ID 已存在，应新增 0 行，检查点不倒退。

提交前受控异常：如果事件写入和检查点更新都在同一个事务内，`rollback` 后可见行数和检查点应仍为 20,000。关闭连接再打开数据库，重放新增事件应插入 1 行并同步推进检查点。晚到事件不是重复事件；若 ID 新且合法，当前教学政策会接受并重新算历史聚合，最终行数预期 20,002。

个人练习 A 的预设错误：`COMMIT_EARLY=True` 会先提交数据，再在写检查点前抛异常。失败后预计看到 1 行数据、检查点仍为 0，二者不一致。改成 `False` 后，同样故障应该把数据和位置一起回滚到 0；随后正常重试只保留 1 行，检查点为 1。这里是受控 Python 异常与单个 SQLite 数据库的提交边界，不等于机器断电或跨系统 exactly-once。
